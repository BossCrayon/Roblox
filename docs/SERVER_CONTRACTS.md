# Implemented server boundaries

`PlayerDomain` is a pure, non-yielding rules module. It validates loaded profiles, recomputes base stats, owns progression/resources/acting/loadout/cast reservations, caps rewards, and produces persistence snapshots. Each state is independent. Objective signals are emitted by trusted effect outcomes, NPC damage decisions and nearby server prompt interactions, never by a remote-supplied reward.

`SessionStore` injects DataStoreService's atomic UpdateAsync backend. Acquisitions, saves and releases are owner/lease checked. Busy handles serialize saves; bounded exponential retries preserve ownership. Operation IDs acknowledge a release that committed before its response failed. Corrupt/future profiles and envelopes are left untouched. The bootstrap refreshes the lease with full saves and freezes gameplay when ownership cannot be maintained. Live servers never use Studio's explicitly labeled volatile backend.

`Bootstrap` creates three RemoteEvents: Intent, State, Effect. Intent has a per-player token bucket and a fixed action set: Sync, Drink, Equip, Cast, Melee. It reads only known, bounded fields; there is no remote for acting rewards, arbitrary state mutation, gold grants, damage amounts or Studio mastery. It validates both before reserving a cast and after the cast time. Failed effects refund reserved spirituality while retaining cooldowns. Death cancels pending casts. All data mutations finish without yielding; saves happen asynchronously against snapshots.

`EffectService` dispatches immutable, server-selected operation kinds. NPC targets must exist in the registered tagged folder, be alive, obey owner restrictions and pass range/line-of-sight checks. Ground positions must be finite. Teleports additionally verify world bounds, support and character-sized occupancy. Recording/stealing uses a fixed NPC power whitelist rather than arbitrary client ability IDs. Portals are owner-only and capped to a pair; summons are bounded. A custom pathway can reuse handlers via data; new mechanics require new trusted handlers.

`WorldService` owns procedural NPCs, hit decisions, statuses, rewards, exposure and whispers. Only a recent server-recorded player hit can receive a kill reward. Pickpocket loot is one-time per NPC. Resistance shortens low-tier status duration against stronger NPCs; control/parasitism reject stronger sequences. NPC damage checks dodge, one-use lethal substitutes, shields and graft reflection. All status, summon, NPC and gate loops run on fixed schedules, not RenderStepped. CollectionService tags identify Enemy, MysticDoor, FlameAnchor and MysticalExposure objects.

The client sends input intent and renders read-only server snapshots. It owns the HUD, camera limits and bounded pools for original neon pulses/highlights. It cannot change the server's player profile, inventory, hitbox or timers. VFX/SFX hook names are public and carry no authority; original audio assets are not supplied.

The horizontal movement guard rejects large unauthorized displacement but is not a complete physics or movement anti-cheat. Engine tests and gameplay measurements remain required. Pure and mocked-adapter tests do not prove Roblox networking, physics or DataStore service behavior.
